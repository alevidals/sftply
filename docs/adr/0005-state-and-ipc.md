# ADR-0005: State ownership and typed IPC

- **Status:** Proposed
- **Date:** 2026-11-05

## Context

The app mixes slow server-derived data (directory listings), real-time pushed state (transfers, session lifecycles), and high-frequency client state (selection, cursor, filters). Putting everything into one store causes stale data, over-rendering, and duplicated truth. Handwritten IPC types drift from Rust.

## Decision

1. **TanStack Query** owns directory listings and one-shot server queries.
   - Key: `["fs", scopeKey, path]`, where `scopeKey` is `"local"` or `"remote:<sessionId>"`.
   - Window-focus refetch off; explicit refresh and targeted invalidation.
   - `keepPreviousData` for navigation; mutations invalidate current + parent.
2. **Zustand** owns client and pushed state:
   - UI layout, theme, density, dialog;
   - tabs, active tab, per-tab paths, active pane;
   - selection/cursor/filter per pane;
   - transfer projection from `transfer://delta` events;
   - session snapshots from `session://state`.
3. **Event bridge** subscribes once at app startup; components never subscribe to raw Tauri events.
4. **Typed IPC** generated by `tauri-specta`:
   - Rust is the source of truth for commands, DTOs and events.
   - `src/lib/ipc/bindings.ts` is generated; CI fails on diff.
   - A single invoke wrapper normalizes `AppError`.
5. **No business logic in components.** Capability checks, conflict policy, resume decisions and path validation live in Rust. Components render capabilities and dispatch intents.
6. **Optimistic updates only where safe:** rename may update the listing optimistically with rollback; delete/create/transfer completion wait for backend confirmation.
7. **Selectors everywhere:** Zustand consumers subscribe to the smallest slice; transfer rows subscribe individually to avoid re-rendering the whole panel.

## Consequences

**Positive**

- One owner per kind of state; no duplication between Query and Zustand.
- High-frequency transfer updates do not invalidate directory queries.
- Contract drift is caught at compile time and in CI.
- UI remains responsive with large lists and many transfers.

**Negative / accepted**

- Generated bindings require a Rust-side build step and CI check.
- Event-projected Zustand state needs careful reducer tests and rehydration after reconnect.
- Two state libraries require documented conventions (which state goes where).

## Alternatives considered

- **All in Zustand:** reimplements caching, deduplication, retries, and invalidation.
- **All in TanStack Query:** poor fit for cursor/selection and high-frequency pushed progress.
- **Handwritten types:** guaranteed drift; rejected.
- **Redux Toolkit:** more ceremony and bundle weight for no product benefit.
- **Global event subscriptions per component:** listener storms and missed events during remounts.

## Validation

Phase 1 delivers the generated binding and event bridge. Phase 2/4 tests cover selection reducers and transfer event projection. A lint rule/CI check prevents direct `invoke` calls outside `lib/ipc` and feature `api.ts` modules.
